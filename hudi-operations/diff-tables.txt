Data files/Base files:
=========================
Hudi stores data in columnar parquet format and is called as data files/base files.
data files/base files are interchangeably used in general, but both mean the same.

Delta log files:
================
In MOR table type, updates are sent to delta log files, which is stored in avro format. these delta files are always associcated with a base file.
lets say we have a data file called data_file_1, any updates to records in data_file_1, will be added as mew log file.
and hudi will do real time merge of records in base file and its corresponding delta log files while serving read queries.

File groups:
============
In general, there could be a lot of data files depending on how much data is stored. each data file and its corresponding delta log files 
form one file group. in case of COW, its a lot simpler as there is only one base file.

File versions:
=============
In the context of COW, whenever an update happens to a data file, a newer version of the data file will be created which 
contains merged records from older data file and newer incoming records.

Two types of tables:
====================
COW and MOR:

write latency: COW has higher write latency when compared to MOR due to the synchronous merge happening during write.

Read latency: since we have to do real time merge in MOR, MOR needs to have higher read latency when compared to COW. but if we 
configure appropriate compation strategies based on our needs, MOR could play out well.

update cost: I/O cost is going to be higher for COW since we create newer data files for every batch of write. MOR has very minimal I/o cost since go into
delta log files.
